## 1. 目標與範圍

有人送出 Google 表單後，資料**自動**進到 App 的 `bookings` 表，狀態 `pending`，讓總務在既有後台（含剛做好的衝突拖曳看板）審核。

**要做**
- 表單端：Google Apps Script `onFormSubmit` 觸發器 → 帶密鑰 POST 到 App。
- App 端：新 endpoint `POST /api/intake/form` → 解析器 → 寫入 `bookings`。
- 去重（Apps Script 會重送）、失敗不整包丟掉、稽核紀錄。

**不做（本期）**
- 不自動核可（一律 `pending`）。
- 不自動比對「取消/異動」到既有預約去改它 —— 只記成一筆待辦讓人工處理。
- 不改表單題目。

## 2. 架構

```
使用者送出表單
      │
      ▼
Google 試算表(回應) ── onFormSubmit(installable trigger) ──► Apps Script
                                                              │  組 payload（只做「題目→key」對應，不解析內容）
                                                              │  UrlFetchApp.fetch(POST, X-Intake-Secret)
                                                              ▼
                                       App 後端  POST /api/intake/form
                                                 ├─ 驗密鑰 + 大小限制
                                                 ├─ 查 form_intake_log 去重
                                                 ├─ formParser：自由文字 → 多筆 booking 草稿
                                                 ├─ findBestMatchingRoom（重用 rooms.js 既有邏輯）
                                                 ├─ 寫入 bookings（status=pending）
                                                 │    對不到場地 / parse 失敗 → 落到虛擬場地「💒 由教會分配」
                                                 │    purpose 前綴【待人工確認】+ 原文
                                                 └─ 寫 form_intake_log（原始 payload + 結果 + needsReview）
                                                 ▼
                                       回應 { ok, created:[ids], needsReview:[...], duplicate:false }
                                                 │
                              Apps Script：非 2xx 或 needsReview 不空 → 寄信通知總務
```

**設計原則：Apps Script 不解析內容**，只把題目答案原封不動包成 JSON。所有解析在後端，方便測試、改規則時只需重部署後端、不用動表單。

## 3. 表單欄位對應

Apps Script 依「題目標題」對應到下列 key（用標題比對，容忍前後空白）：

| 表單題目 | payload 路徑 | 說明 |
|---|---|---|
| 牧區 | `borrower.pastoralZone` | |
| 姓名 | `borrower.name` | |
| 連絡電話 | `borrower.phone` | |
| 場地借用類型 | `type` | `一般借用` / `婚禮＆重要場地借用` / `取消&異動` |
| 婚禮＆活動名稱 | `wedding.eventName` | |
| 借用內容 | `wedding.content` | `結婚典禮`/`婚禮彩排`/`特殊活動＆場地` |
| 借用日期 | `wedding.date` | 絕對日期 `YYYY-MM-DD` |
| 婚禮時間＆其他場地/時間 | `wedding.slotsText` | 多行自由文字 |
| 取消or更新 | `changeReq.mode` | `取消` / `更新` |
| 場地取消 | `changeReq.cancelRoom` | |
| 取消原因 | `changeReq.cancelReason` | |
| 更新資料(人數.日期.時間) | `changeReq.updateInfo` | |
| 更新原因 | `changeReq.updateReason` | |
| 一般場地借用(借士林堂…) | `general.month` | `八月份` / `九月份` |
| 八-1(8/3-8/9)… / 九-1(8/31-9/06)… | `general.weeks[]` | `{ label: 題目標題, text: 答案 }`；label 內含週日期範圍，解析器要用 |

> 週欄位的**題目標題本身**帶了日期範圍（例：`八-3( 8/17-8/23) -借士林堂請在位置寫士林`），解析器靠它把「週幾」換算成實際日期，所以 Apps Script 要把 label 原樣送過來。

## 4. API 契約：`POST /api/intake/form`

### Request

Headers：
- `Content-Type: application/json`
- `X-Intake-Secret: <與後端 env FORM_INTAKE_SECRET 相同的長隨機字串>`

Body：
```jsonc
{
  "formResponseId": "2_ABaOnu...",          // Apps Script e.response.getId()，用於去重
  "submittedAt": "2026-09-09T04:12:33.000Z",
  "borrower": { "pastoralZone": "大安6區", "name": "王小明", "phone": "0912345678" },
  "type": "一般借用",
  "general": {
    "month": "九月份",
    "weeks": [
      { "label": "九-3(9/14-9/20) -借士林堂請在位置寫士林",
        "text": "週日/1500-1730/小組聚會/30/B1-4\n週三/1930-2130/禱告會/12/五教" }
    ]
  },
  "wedding": null,
  "changeReq": null
}
```
（`wedding` / `changeReq` 依 `type` 擇一有值，其餘為 `null`。）

### Response（200）
```jsonc
{
  "ok": true,
  "formResponseId": "2_ABaOnu...",
  "duplicate": false,
  "created": [1234, 1235],              // 成功寫入的 booking id
  "needsReview": [                       // 有寫入但需人工確認（落到「由教會分配」）
    { "bookingId": 1236, "reason": "場地對不到：『五教B』", "raw": "週三/1930-2130/禱告會/12/五教B" }
  ],
  "skipped": [                           // 完全無法處理、未寫入
    { "reason": "整格空白", "raw": "" }
  ]
}
```

### 錯誤
| 狀態 | 情況 |
|---|---|
| 401 | 密鑰缺少 / 不符 |
| 400 | JSON 格式錯 / 缺 `formResponseId` / 缺 `type` |
| 413 | body 超過 64KB |
| 200 `duplicate:true` | `formResponseId` 已處理過（Apps Script 重送）→ 不重複寫入 |
| 500 | 後端未預期錯誤（Apps Script 會重試 + 寄信） |

### 冪等
以 `form_intake_log.form_response_id` 唯一鍵擋重送。命中即回上次結果的摘要、`duplicate:true`，不再寫任何 booking。

## 5. 解析器規格（`backend/intake/formParser.js`）

輸入：上面的 payload。輸出：`{ drafts: BookingDraft[], skipped: [...] }`，
`BookingDraft = { branch, roomMatch, booking_date, start_time, end_time, attendance_count, purpose, booking_type, needsReview?, raw }`

### 5.1 依 `type` 分流 + booking_type 對應

| 表單 type | 進一步依據 | 寫入 `booking_type`（DB 允許值：`一般借用/婚禮/重要/取消或異動`） |
|---|---|---|
| 一般借用 | — | `一般借用` |
| 婚禮＆重要場地借用 | `wedding.content = 結婚典禮 / 婚禮彩排` | `婚禮` |
| 婚禮＆重要場地借用 | `wedding.content = 特殊活動＆場地` | `重要` |
| 取消&異動 | — | `取消或異動` |

### 5.2 一般借用

1. 依 `general.month` 決定要讀哪些 `weeks[]`（八月 → 八-1..八-4；九月 → 九-1..九-4）。實際上直接把 payload 帶來的每個 `weeks[]` 都處理即可。
2. 每個 week：
   - 從 `label` 抓日期範圍：`/(\d{1,2})\s*\/\s*(\d{1,2})\s*[-~]\s*(\d{1,2})\s*\/\s*(\d{1,2})/` → 起訖 `M/D`，年份用 **2026**（表單標題）。跨年（例：`九-1(8/31-9/06)`）要處理。
   - 由起日推出該週「週一…週日 → 實際日期」對照表（用起訖實際涵蓋的 7 天）。
   - `text` 依換行 / 分號切成多行，每行一筆。
3. 每行 tokenizer：以 `/`、`／`、多個空白、`,`、`，` 切 token，再逐一分類：
   | 分類 | 判斷 | 產出 |
   |---|---|---|
   | 週幾 | `/^(週|星期|禮拜)?[一二三四五六日天]$/` | → 對照表得 `booking_date` |
   | 時段 | `/^\d{1,2}[:：]?\d{2}\s*[-~到至]\s*\d{1,2}[:：]?\d{2}$/` | 正規化為 `HH:MM:SS`（`1500`→`15:00:00`） |
   | 人數 | `/^\d{1,3}\s*人?$/` | `attendance_count` |
   | 其他 | 前一個未被吃掉的 → 場地候選；再其餘 → 併成 `purpose` | |
   - 場地候選丟 `findBestMatchingRoom(cand, dbRooms, branch)`；解析到 → `roomMatch`；否則整行剩餘當 purpose、`needsReview`。
   - `branch`：該行文字含「士林」→ `士林堂`；否則 `仁愛堂`（可設 env 預設）。
4. 缺時段 / 缺週幾 → 該行 `skipped`（回報，不寫）。缺人數 → 寫入但 `attendance_count = null` 且 `needsReview`。

**範例**
| 原始行 | 解析結果 |
|---|---|
| `週日/1500-1730/小組聚會/30/B1-4` | date=該週日, 15:00–17:30, 30 人, room≈`B1-互動區第4區塊`, purpose=`小組聚會` |
| `週三 1930-2130 禱告會 12 五教` | date=該週三, 19:30–21:30, 12 人, room≈`B2-第五教室`, purpose=`禱告會` |
| `週六/1400-1600/區聚/士林副堂/40` | branch=士林堂, room≈`B1-副堂`(士林), 40 人 |
| `週日 小組` | skipped（無時段） |

### 5.3 婚禮＆重要

- `wedding.date` 為絕對日期，直接用。
- `wedding.slotsText` 多行，每行文法同 5.3 tokenizer，但**若該行沒有週幾就套用 `wedding.date`**；有週幾則以 `wedding.date` 所在週換算。
- `purpose` 前置 `wedding.eventName`：`【{eventName}】{該行事由}`。
- 沒有任何可解析行 → 至少寫一筆：`booking_date = wedding.date`、room 落「由教會分配」、`purpose = 【{eventName}】{slotsText 原文}`、`needsReview`。

### 5.4 取消&異動

本期不自動改既有預約。寫一筆 `pending`、`booking_type=取消或異動`、room 盡量比對（`changeReq.cancelRoom`）否則「由教會分配」、`booking_date` 若能從 `updateInfo` 抓到日期就用、否則今天：
- `mode=取消`：`purpose = 【取消】{cancelRoom}｜原因：{cancelReason}`
- `mode=更新`：`purpose = 【異動】{updateInfo}｜原因：{updateReason}`
一律 `needsReview`。

## 6. 寫入 `bookings` 的規則

| 欄位 | 值 |
|---|---|
| `room_id` | `roomMatch.id`；對不到 → 該 branch 的「💒 由教會分配」room id（migration 013 已建） |
| `user_email` | env `FORM_INTAKE_EMAIL`（預設 `form-intake@local`）— 欄位 NOT NULL |
| `full_name` / `phone` / `pastoral_zone` | `borrower.*` |
| `booking_date` / `start_time` / `end_time` | 解析結果 |
| `attendance_count` | 解析到的數字，否則 `null` |
| `booking_type` | 見 5.1 |
| `purpose` | 解析事由；`needsReview` 時前綴 `【待人工確認】` + 原始行 |
| `status` | 一律 `'pending'` |
| `created_at` | DB 預設 |

- **不跑硬性 overlap 擋擋**（不要因為撞時段就不寫）。撞到就讓它以 pending 進去，總務用衝突看板處理 —— 剛好接上現有流程。
- 多筆一次寫：逐筆 insert 或 `insert([...])` 批次；任一筆失敗記入 `skipped`，不影響其他筆。
- 全部包在一次 `form_intake_log` 紀錄裡。

## 8. 安全性

- **密鑰**：`FORM_INTAKE_SECRET` = 32+ bytes 隨機（`openssl rand -hex 32`）。後端存 env，Apps Script 存 Script Properties（不要寫死在程式碼）。
- 比對用 `crypto.timingSafeEqual`。
- 只收 HTTPS；body 上限 64KB；`express.json({ limit: '64kb' })` 專用於這條 route。
- 這條 route **不掛** `authMiddleware`（外部服務呼叫），改用密鑰中介層；放獨立 router `backend/routes/intake.js`。
- Rate limit：同一 `form_response_id` 冪等即可擋重送；另可加簡單 IP/秒級限流。
- Log 不要印完整電話 / 姓名以外的多餘 PII；`raw_payload` 存 DB 供稽核即可。
- 失敗回應訊息不要洩漏內部堆疊。

## 9. Apps Script 範本（表單回應試算表 → 擴充功能 → Apps Script）

```javascript
const ENDPOINT = 'https://<你的後端網域>/api/intake/form';
// Script Properties 設定 INTAKE_SECRET
const SECRET = PropertiesService.getScriptProperties().getProperty('INTAKE_SECRET');
const NOTIFY_EMAIL = 'a0970927705@gmail.com';

// 題目標題 → payload key（標題有改就要同步這裡）
function buildPayload(e) {
  const byTitle = {};
  e.response.getItemResponses().forEach(ir => {
    byTitle[ir.getItem().getTitle().trim()] = ir.getResponse();
  });
  const t = s => (byTitle[s] || '').toString();

  const weeks = [];
  e.response.getItemResponses().forEach(ir => {
    const title = ir.getItem().getTitle().trim();
    if (/^[八九][-－]\d/.test(title)) weeks.push({ label: title, text: ir.getResponse() });
  });

  return {
    formResponseId: e.response.getId(),
    submittedAt: e.response.getTimestamp().toISOString(),
    borrower: { pastoralZone: t('牧區'), name: t('姓名'), phone: t('連絡電話') },
    type: t('場地借用類型'),
    general: { month: t('一般場地借用(借士林堂請在位置寫士林)'), weeks },
    wedding: {
      eventName: t('婚禮＆活動名稱'), content: t('借用內容'),
      date: t('借用日期'),
      slotsText: t('婚禮時間＆其他場地/時間\n例:週日/1100-1700/婚禮場佈/10/B1-1 \n週日/1500-1730/婚禮愛宴/150 B1-4.5.6區塊 週日/1230-1730/新娘房/20/副堂'),
    },
    changeReq: {
      mode: t('取消or更新'),
      cancelRoom: t('場地取消'), cancelReason: t('取消原因'),
      updateInfo: t('更新資料(人數.日期.時間)'), updateReason: t('更新原因'),
    },
  };
}

function onFormSubmit(e) {
  const payload = buildPayload(e);
  try {
    const res = UrlFetchApp.fetch(ENDPOINT, {
      method: 'post',
      contentType: 'application/json',
      headers: { 'X-Intake-Secret': SECRET },
      payload: JSON.stringify(payload),
      muteHttpExceptions: true,
    });
    const code = res.getResponseCode();
    const body = res.getContentText();
    if (code < 200 || code >= 300) {
      notify('表單匯入失敗 HTTP ' + code, body + '\n\n' + JSON.stringify(payload, null, 2));
      return;
    }
    const data = JSON.parse(body);
    if ((data.needsReview && data.needsReview.length) || (data.skipped && data.skipped.length)) {
      notify('表單匯入：有需人工確認的項目',
        JSON.stringify({ created: data.created, needsReview: data.needsReview, skipped: data.skipped }, null, 2));
    }
  } catch (err) {
    notify('表單匯入例外', String(err) + '\n\n' + JSON.stringify(payload, null, 2));
  }
}

function notify(subject, body) {
  MailApp.sendEmail(NOTIFY_EMAIL, '[場地表單] ' + subject, body);
}
```
安裝：Apps Script 編輯器 → 觸發器 → 新增 → `onFormSubmit` / 事件來源「表單」/ 類型「提交表單時」。**必須用「安裝式」觸發器**（`UrlFetchApp` / `MailApp` 在簡易觸發器受限）。

## 11. 邊界情況

| 情況 | 處理 |
|---|---|
| Apps Script 重送同一份回應 | `form_response_id` UNIQUE → `duplicate:true`，不重寫 |
| 一格週欄位空白 | 該 week 跳過，不算錯 |
| 一行只有事由沒時段 | `skipped`，回報 Apps Script 寄信 |
| 場地寫「B1-4.5.6」多區塊 | P1：整串丟 `findBestMatchingRoom`，對不到 → 由教會分配 + needsReview（多區塊拆分列 P2） |
